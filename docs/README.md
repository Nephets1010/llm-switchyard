# 架构决策记录（ADR）

记录本项目所有**架构级**决策：决策背景、结论、以及被否掉的备选方案。

写 ADR 的目的不是留档，而是**让后来的维护者能判断「为什么是这样」**。
一个用 200 行自己实现的熔断器，如果没说清「为什么不用 Resilience4j」，
三年后另一个人会当成技术债去「优化」掉。

## 模板

新增 ADR 时复制这个结构：

```markdown
# ADR-XXXX：<决策的一句话>

- **状态**：提议 / 已接受 / 已废弃
- **日期**：YYYY-MM-DD
- **影响范围**：哪些模块 / 哪些文件

## 背景
为什么需要做这个决策。**包含否定备选方案的事实依据**，不要只写「不够好」。

## 决策
一句话说清做了什么。

## 后果
### 正面
### 负面（必须诚实面对）
```
